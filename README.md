# Olist: кто покупает повторно

**[Открыть полное исследование в Jupyter Notebook](olist_retention_analysis.ipynb)**

Какие категории первой покупки подходят для теста второй покупки и как повторные покупки различаются при доставке вовремя и с опозданием?

## Данные

Источник — [Olist Brazilian E-Commerce](https://www.kaggle.com/datasets/olistbr/brazilian-ecommerce), опубликованный Olist по лицензии [CC BY-NC-SA 4.0](https://creativecommons.org/licenses/by-nc-sa/4.0/).

- [`data/buyer_analysis.csv`](data/buyer_analysis.csv) — подготовленная SQL-выгрузка: одна строка на покупателя с полным окном 180 дней.
- [`data/delivery_after_receipt.csv`](data/delivery_after_receipt.csv) — два окна повторов после получения, отдельно для доставки вовремя и с опозданием. SQL учитывает все последующие заказы; одной даты ближайшего повтора недостаточно.

Покупатель — `customer_unique_id`; учитываются заказы со статусом `delivered`. Граница наблюдения — **31.07.2018 23:59:59**. Одновременные первые заказы объединяются и не считаются повтором. Имена и адреса покупателей в выгрузки не включены.

## Основные выводы

- **Повторы и категории:** за 180 дней снова купили 1 358 из 49 452 покупателей — 2,75%. Среди 17 крупных категорий лидируют сумки: 4,81% (50 из 1 039), и домашний текстиль: 4,49% (214 из 4 769). В Cool stuff — 1,30% (31 из 2 382).
- **Месячные когорты:** у сумок доля выше, чем у Cool stuff, в 11 из 13 месяцев с января 2017 по январь 2018. Январские 11,11% у сумок основаны всего на трёх повторных покупателях из 27.
- **Доставка:** за полные 180 дней после получения снова купили 829 из 44 279 покупателей с доставкой вовремя — 1,87%, и 32 из 2 332 покупателей с опозданием — 1,37%. Разница около 0,50 п.п. не доказывает причинный эффект задержки. У 526 покупателей ближайший повтор был оформлен до полного получения первой покупки или одновременно с ним.

## Рекомендации

Домашний текстиль подходит для набора участников CRM-пилота: при близкой к сумкам доле повторов его база в 4,6 раза больше. После получения первой покупки сравнить предложение второй покупки с текущими коммуникациями среди тех, кто ещё не оформил повтор. Помимо повторов оценить маржу на покупателя с учётом скидок и стоимости сообщений. Высокая исходная доля повторов не гарантирует больший эффект предложения.

Среди покупателей с задержкой сравнить дополнительные уведомления и помощь с обычной поддержкой; учесть стоимость обращений, жалобы и отписки.

В обоих тестах случайно распределять покупателей в группы. Основная метрика — доля с доставленным повторным заказом, оформленным за полные 180 дней после распределения. Перед запуском рассчитать число участников.

## Запуск notebook в Windows

Установить Python 3.12, скачать репозиторий и открыть PowerShell в его корне:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install pandas matplotlib notebook
.\.venv\Scripts\python.exe -m notebook
```

Открыть `olist_retention_analysis.ipynb`, выбрать ядро созданного окружения и выполнить **Kernel → Restart Kernel and Run All Cells**. Обе аналитические таблицы уже включены в проект; графики и таблицы сохранены внутри notebook.

## Пересчёт SQL

Создать SQLite-базу в DBeaver, выполнить [`00_setup.sql`](sql/00_setup.sql) и импортировать CSV из Olist в существующие таблицы, сопоставив колонки по заголовкам:

| CSV | Таблица |
| --- | --- |
| `olist_orders_dataset.csv` | `orders` |
| `olist_customers_dataset.csv` | `customers` |
| `olist_order_items_dataset.csv` | `order_items` |
| `olist_products_dataset.csv` | `products` |
| `product_category_name_translation.csv` | `category_translation` |

Если база уже заполнена, повторный импорт не нужен. Выполнить остальные файлы из [`sql/`](sql/) по порядку: `01` → `02` → `03` → `04`. Они пересоздают только аналитические представления; исходные таблицы сохраняются.

Из `04_delivery.sql` экспортировать **предпоследний SELECT** в `data/delivery_after_receipt.csv`, **последний SELECT** — в `data/buyer_analysis.csv`, оба с заголовками. При смене данных обновить обе выгрузки, выполнить notebook и пересмотреть выводы. Исходные CSV и локальные базы исключены из Git.

## Ограничения

Данные исторические, категории выбраны после просмотра результатов, группы доставки не уравнены по составу покупателей. Первая наблюдаемая покупка не обязательно первая в жизни клиента. Для маркетплейса с разными категориями низкая общая доля повторов сама по себе не доказывает плохое удержание; отсутствие покупки за полгода не означает окончательный уход. Анализ помогает выбрать гипотезы, но не оценивает эффект будущих экспериментов.
