# Olist: кто покупает повторно

**[Открыть исследование в Jupyter Notebook](olist_retention_analysis.ipynb)**

В каких категориях покупатели чаще возвращались за 180 дней и как различалась доля повторных покупок при доставке вовремя и с опозданием? Анализ помогает выбрать сегмент для CRM-теста и проверить гипотезу о поддержке покупателей при задержке.

## Основные результаты

- **За 180 дней снова купили 1 358 из 49 452 покупателей — 2,75%.** У каждого есть полный срок наблюдения.
- **Сумки и домашний текстиль лидируют среди 17 крупных категорий:** 4,81% (50 из 1 039) и 4,49% (214 из 4 769). У сумок доля выше, чем у Cool stuff, в 11 из 13 месячных когорт; общая доля в Cool stuff — 1,30%.
- **За полные 180 дней после получения повторно купили 1,87% при доставке вовремя и 1,37% после опоздания:** 829 из 44 279 и 32 из 2 332. Разница 0,50 п.п. описывает группы, но не доказывает эффект задержки.

Для первого CRM-пилота подходит домашний текстиль: при близкой к сумкам доле повторов его база в 4,6 раза больше. Проверить предложение второй покупки в случайно назначенной контрольной и тестовой группах, сравнить повторы и маржу с учётом расходов. Отдельно протестировать уведомления и поддержку среди покупателей с задержкой; перед тестами рассчитать необходимое число участников.

## Данные и SQL

Источник — [Olist Brazilian E-Commerce](https://www.kaggle.com/datasets/olistbr/brazilian-ecommerce), опубликованный Olist по лицензии [CC BY-NC-SA 4.0](https://creativecommons.org/licenses/by-nc-sa/4.0/). В проекте используются подготовленные аналитические таблицы из этого набора; имена и адреса покупателей не включены.

Покупатель — `customer_unique_id`; учитываются заказы со статусом `delivered`. Граница наблюдения — **31.07.2018 23:59:59**. Одновременные первые заказы объединяются и не считаются повтором.

- `data/buyer_analysis.csv` — итоговая SQL-выгрузка: одна строка на покупателя с полным окном 180 дней. Из неё notebook пересчитывает основной показатель, категории, месячные когорты и сравнение доставки от даты покупки.
- `data/delivery_after_receipt.csv` — четыре агрегата отдельного SQL-запроса для двух окон после получения. Он учитывает **все последующие заказы**; одной даты ближайшего повтора недостаточно. Проценты рассчитываются в notebook.

Обе таблицы пересчитаны из пяти исходных CSV и сверены с предыдущей версией: все строки и численности совпали. Выполнение пяти SQL-файлов и notebook проверено.

SQL выполняется в SQLite по порядку:

| Файл | Назначение |
| --- | --- |
| [00_setup.sql](sql/00_setup.sql) | Пять исходных таблиц и индексы |
| [01_data_quality.sql](sql/01_data_quality.sql) | Ключи, связи, пропуски и границы периода |
| [02_repeat_purchases.sql](sql/02_repeat_purchases.sql) | Покупатели, последовательность покупок и полные 180 дней |
| [03_first_categories.sql](sql/03_first_categories.sql) | Категории первых заказов и месячные сравнения |
| [04_delivery.sql](sql/04_delivery.sql) | Доставка, окна после получения и две выгрузки |

Для пересчёта с исходных данных создать SQLite-базу в DBeaver, выполнить `00_setup.sql` и импортировать CSV из Olist в существующие таблицы, сопоставив колонки по заголовкам:

| Исходный CSV | Таблица |
| --- | --- |
| `olist_orders_dataset.csv` | `orders` |
| `olist_customers_dataset.csv` | `customers` |
| `olist_order_items_dataset.csv` | `order_items` |
| `olist_products_dataset.csv` | `products` |
| `product_category_name_translation.csv` | `category_translation` |

Если база уже заполнена, повторный импорт не нужен. Затем выполнить `01`–`04`. Проверить результаты запросов качества: число строк, дубликаты ключей и потерянные связи. Аналитические запросы пересоздают только представления; исходные таблицы сохраняются.

Предпоследний запрос `04_delivery.sql` экспортировать с заголовками в `data/delivery_after_receipt.csv`, последний — в `data/buyer_analysis.csv`. При смене данных обновить **обе** выгрузки и пересмотреть текстовые выводы. Исходные CSV и локальные базы исключены из Git.

## Запуск в Windows

Готовые таблицы включены в проект: для запуска notebook импорт SQLite не нужен. Установить Python 3.12, скачать репозиторий и открыть PowerShell в его корне:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install pandas matplotlib notebook
.\.venv\Scripts\python.exe -m notebook
```

Открыть `olist_retention_analysis.ipynb`, выбрать ядро созданного окружения и выполнить **Kernel → Restart Kernel and Run All Cells**. Таблицы и графики сохранены внутри notebook для просмотра на GitHub.

## Ограничения

Исследование описательное: категории выбраны после просмотра результатов, группы доставки не уравнены по составу покупателей. Первая наблюдаемая покупка не обязательно первая в жизни клиента; отсутствие повтора за полгода не означает окончательный уход. Данные исторические.
